# Ninja Gaiden Black — Patch Research

Ninja Gaiden Black（原版 Xbox，USA）`default.xbe` 的补丁整理：镜头相关改动、R3 默认设置、镜头转速、HDDKey 检查。

补丁与思路来自 **Lucaz**。本仓库只记录每个机能对应的改法和分析，不包含游戏文件或 XBE。

> English summary: byte patches for the USA release of *Ninja Gaiden Black* (original Xbox) `default.xbe` — inverted camera, NGII-style horizontal camera during Ultimate Technique / Ninpo, R3 default camera setting, camera speed multiplier, and disabling the HDD key check. No game data is included.

| 项目 | 值 |

## 3. 各机能的改法

### A. 镜头反转 + 奥义/忍法时的水平镜头

**效果（按补丁说明）**：反转镜头；R3 默认镜头反转；奥义（Ultimate Technique）和忍法（Ninpo）时增加水平方向的镜头操作，类似 NGII。

**第 1 步：钩子**（文件偏移 `0x37A37`，VA `0x47A37`）

```
Find:    EB 07 8D A4 24 00 00 00 00 0F BF 30 0F
Replace: E8 97 A2 D7 00 90 90 90 90 0F BF 30 0F
```

原指令是一个 `jmp` 加 7 字节对齐填充，没有实际功能。改成 `call` 加 4 个 NOP，不需要搬动任何原指令。`call` 的目标是 VA `0xDC1CD3`，对应文件偏移 `0x455553`。

**第 2 步：代码洞**（写到文件偏移 `0x455553`，共 132 字节）

```
0F 57 25 90 9C 3F 00 66 83 3D E4 95 58 00 00 75 6C 80 3D 60 5A DB 00 0E 74 5A
80 3D 60 5A DB 00 0F 74 51 80 3D 61 5A DB 00 0E 74 48 80 3D 61 5A DB 00 0F 74
3F 80 3D 97 98 DB 00 0E 74 36 80 3D 97 98 DB 00 0F 74 2D 80 3D 90 3E DA 00 0E
74 24 80 3D 90 3E DA 00 0F 74 1B 80 3D 2C 40 DA 00 01 74 12 66 8B 35 CC 75 4B
00 66 81 EE D0 02 66 83 FE 20 72 09 66 83 3D E4 95 58 00 00 C3 83 E8 04 66 89
10 C3
```

写入位置在 `XON_RD` 段，该段带可执行和预加载标志，原来这 132 字节全为 0，不会和原有代码冲突。

**反汇编**（VA `0xDC1CD3` 起）：

```asm
xorps  xmm4, [0x3F9C90]        ; 把摇杆系数取反，两个轴都反转
cmp    word [0x5895E4], 0
jnz    WRITE
cmp    byte [0xDB5A60], 0x0E   ; 一组状态检查，命中则走 RESTORE
je     RESTORE                 ;   （0xDB5A60, 0xDB5A61, 0xDB9897, 0xDA3E90
cmp    byte [0xDB5A60], 0x0F   ;     各检查 0x0E 和 0x0F）
je     RESTORE
...
cmp    byte [0xDA402C], 1
je     RESTORE
mov    si, [0x4B75CC]
sub    si, 0x2D0
cmp    si, 0x20
jb     WRITE                   ; [0x4B75CC] 在 720..751 之间
RESTORE:
cmp    word [0x5895E4], 0
ret                            ; 保持原来的摇杆读取位置
WRITE:
sub    eax, 4                  ; 摇杆读取位置往前挪 4 字节
mov    [eax], dx               ; dx 此时为 0，把被挪过去的第一个轴写成 0
ret
```

**机制**（来自钩子周围原代码的反汇编）：
- 钩子在镜头函数里读摇杆那个循环的入口。循环读 `[eax]`、`[eax+2]` 两个轴，`eax` 初始是 `0xD219CC + 玩家序号 × 0x78`。
- 反转：`0x3F9C90` 处第一个 dword 是 `0x80000000`，对 `xmm4`（摇杆系数 1/127）取反，两个轴都反转。
- `WRITE` 路径把读取位置往前挪 4 字节，即从 `0xD219CC / 0xD219CE` 这一对改读 `0xD219C8 / 0xD219CA` 这一对，同时把第一个轴清零。此时第一个轴（镜头垂直方向）为 0，第二个轴（镜头水平方向）有值，所以只有水平镜头可以操作。
- `WRITE` 的触发条件：`[0x5895E4] ≠ 0`，或者没有命中前面的状态检查并且 `[0x4B75CC]` 落在 720 到 751 之间。
- 两条路径返回前的 `cmp` 对后面的代码没有影响，因为钩子后面的指令不依赖标志位。

### A′. 精简版（只做镜头反转）

补丁说明（Lucaz 原话）：此版本不影响忍法，但同样会反转镜头，因为两版共用同一段例程。说明里只提了忍法，没有说奥义。从代码看，这版没有针对奥义或忍法的判断，只是在 `[0x5895E4] ≠ 0` 时才改读取位置。Jeremy 实机试过（带第 6 节垂直改动的版本）：**奥义（Ultimate Technique）时镜头可以操作，忍法时不能**，即 `[0x5895E4] ≠ 0` 对应奥义状态，不包括忍法。

**钩子**（文件偏移 `0x37A37`）：

```
Find:    EB 07 8D A4 24 00 00 00 00 0F BF 30 0F
Replace: E8 E8 34 41 00 90 90 90 90 0F BF 30 0F
```

`call` 目标 VA `0x45AF24`，对应文件偏移 `0x44BC64`，在 `.data` 段末尾的空白处。

**代码洞**（文件偏移 `0x44BC64`）：

```
Find:    00 ×44, 92 0A 86 3F 92 0A 86 3F, 00 ×8
Replace: 0F 57 25 90 9C 3F 00 66 83 3D E4 95 58 00 00 74 06 83 E8 04 66 89 10 C3
         （后面接着原来的 00 填充，直到 92 0A 86 3F 92 0A 86 3F 那一段）
```

反汇编：

```asm
xorps  xmm4, [0x3F9C90]        ; 反转
cmp    word [0x5895E4], 0
je     RET
sub    eax, 4                  ; 仅当 [0x5895E4] ≠ 0 时才挪读取位置并清零
mov    [eax], dx
RET:
ret
```

和 A 的区别：去掉了整段状态判断和 `[0x4B75CC]` 的区间判断，所以奥义/忍法期间的水平镜头逻辑没有了，只剩反转。

### B. R3 默认镜头设置

```
Find:    88 1D CC 9A DB 00 C6 05 9D 1A 7F 00 01
Replace: 40 A2 CC 9A DB 00 C6 05 9D 1A 7F 00 01
```

原指令 `mov [0xDB9ACC], bl` 改成 `inc eax; mov [0xDB9ACC], al`。长度相同，写入的默认值从 0 变成 1（假定此处 `eax` 为 0）。之后游戏里仍可自行切换。

### C. 镜头转速

```
Find:    04 02 01 3C 34 33 B3 3E CD CC 0C BF 00 00 10 40
Replace: <新系数> 34 33 B3 3E CD CC 0C BF 00 00 10 40
```

只改前 4 个字节。`04 02 01 3C` 是单精度浮点 `1/127`，即摇杆最大值归一化的系数，改它等于改转速倍率。倍率 `k` 对应的字节可以用下面的方法算：

```python
import struct
print(struct.pack('<f', k / 127).hex(' '))
```

| 倍率 | 字节 | 倍率 | 字节 |
|---|---|---|---|
| 0.75x | `06 83 C1 3B` | 1.25x | `85 42 21 3C` |
| 0.80x | `A0 69 CE 3B` | 1.30x | `D2 B5 27 3C` |
| 0.85x | `3A 50 DB 3B` | 1.35x | `1F 29 2E 3C` |
| 0.90x | `D4 36 E8 3B` | 1.40x | `6C 9C 34 3C` |
| 0.95x | `6E 1D F5 3B` | 1.45x | `B9 0F 3B 3C` |
| **1.00x（原版）** | `04 02 01 3C` | 1.50x | `06 83 41 3C` |
| 1.05x | `51 75 07 3C` | 1.55x | `53 F6 47 3C` |
| 1.10x | `9E E8 0D 3C` | **2.00x** | `04 02 81 3C` |
| 1.15x | `EB 5B 14 3C` | | |
| 1.20x | `38 CF 1A 3C` | | |

> 原补丁说明里的 `2.00x = 1B D5 4B 3C` 实际约是 1.58x，本表已改为正确值 `04 02 81 3C`（指数加 1，倍率正好翻倍）。其余各项已逐个换算核对。

### D. 关闭 HDDKey 检查

```
Find:    3C 33 C0 F3 A6 74 05 1B C0 83 D8 FF
Replace: 3C 33 C0 F3 A6 EB 05 1B C0 83 D8 FF
```

文件偏移 `0x300324`，VA `0x310324`。只改一个字节：`74`（`je`）改成 `EB`（`jmp short`）。

这段代码在比较两个 20 字节的值（`repz cmpsb`，`ecx = 0x14`）：一个是已存的值，另一个是前面调用函数算出来的值。原来不相等时结果非零，走失败分支；补丁让它总是走“相等”的分支（`eax = 0`）。

> 它在校验什么，根据长度（20 字节，和 SHA-1/HMAC 摘要一致）和补丁名称推断为与主机 HDD 密钥绑定的签名检查，大概率是存档签名。这是推断，没有从调用链上完全确认。

## 4. 打补丁的方法

用任意十六进制编辑器打开 `default.xbe`，按上面的 Find 搜索特征码，改成 Replace 的内容。代码洞（A 的 `0x455553`、A′ 的 `0x44BC64`）需要在对应偏移直接写入。

如果 `default.xbe` 还在 XISO 镜像里，不必先解包：
- Redump 来源的 XISO 里，`default.xbe` 从扇区 428961 开始，即镜像偏移 `0x345D0800`。
- 镜像里的偏移 = `0x345D0800` + 上面的文件偏移。
- 补丁前建议确认该位置的前 4 个字节是 `58 42 45 48`（`XBEH`），并检查特征码在该文件里只出现一次。

## 5. 核对状态

**已核对（在 Redump XISO 的 `default.xbe` 上逐字节检查）**
- A、A′、B、C、D 的 Find 特征码在文件里都只出现一次，位置和上表一致。
- A 的 `call` 位移（`0xD7A297`）确实指向 `0x455553`；A′ 的（`0x4134E8`）指向 `0x44BC64`。
- A 的代码洞所在的 132 字节原本全为 0，位于 `XON_RD` 段的原始数据范围内。
- C 里的 `04 02 01 3C` 就是 `1/127`，速度表除 2.00x 外各项换算正确。
- D 修改的是一次 20 字节比较之后的条件跳转。

**推断（读反汇编得出，没有实机验证）**
- `[0x4B75CC]` 在 720 到 751 之间对应奥义/忍法，具体对应哪些招式未确认。
- `0xD219C8/CA` 和 `0xD219CC/CE` 分别是哪根摇杆。
- 循环读到的第一个轴对应镜头垂直方向、第二个轴对应水平方向。这是根据后面的代码怎么使用这两个值推断的：第一个轴乘 0.1 后用来调整镜头高度，第二个轴乘 0.0384 后用作旋转角度，并受相对朝向的限制。
- D 校验的是存档签名。

**尚未做**
- 除第 6 节 A′ 的实验改动之外，其余补丁没有在 xemu 或实机里试玩验证。

## 6. 实验性改动（非 Lucaz 原版）

目标：让奥义/忍法时的镜头垂直方向也能操作。

做法：把 A 的 `WRITE` 路径里清零那条指令去掉。

```
位置: 文件偏移 0x4555D3（A 的代码洞 +0x80）
原:   66 89 10    ; mov [eax], dx
改:   90 90 90    ; nop
```

去掉清零后，被挪到的那一对摇杆轴两个都能传给镜头，所以垂直方向也有输入。如果游戏在这些状态下还有别的限制，可能仍然没有效果。

**A′ 上的同样改法**

```
位置: 文件偏移 0x44BC78（A′ 的代码洞 +0x14）
原:   66 89 10    ; mov [eax], dx
改:   90 90 90    ; nop
```

**状态**：A′ 加上这个改动，已由 Jeremy 实机试过，奥义（Ultimate Technique）时镜头垂直和水平方向都可以操作（360 度），忍法时镜头仍不能操作。没有逐一测试其他状态。A（长版）上的同样改动尚未试过；长版的触发条件里包含忍法，理论上可以覆盖忍法，但这只是从代码推断。
